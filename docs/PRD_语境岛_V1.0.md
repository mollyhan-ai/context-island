## 名词解释

| 术语 | 说明 |
| --- | --- |
| 义项（Sense） | 一个单词在词典中的一条独立释义。多义词有多个义项，本产品的核心任务之一是判断当前语境命中哪一个。 |
| synset | WordNet 中的同义词集合，一个 synset 代表一个独立词义，带稳定编号。本产品的 sense_id 锚定在 synset 上。 |
| sense_id | 词库中每个义项的唯一编号。模型只输出编号，释义文本由系统按编号回填。 |
| **词性（POS）** | 一个**词**的语法类别：名词、动词、形容词、副词等。本产品由 NLP 库确定性标注，不经模型。 |
| **句子成分** | 一个**片段**在句中承担的角色：主语、谓语、宾语、状语、定语等。本产品由模型生成并经交叉校验。 |
| 成分树 | 句子的语法结构标注结果，标明每个片段在句中承担的成分（主语、谓语、状语等）。 |
| CEFR | 欧洲语言共同参考框架，把语言能力分为 A1–C2 六级。本产品用它表达难度目标。 |
| 降级生成 | 规则校验多次不通过时，系统不再重试，改为输出并显式标注"本句未通过难度校验"。 |
| 歧义句 | 语法上存在两种及以上合理解析的句子（如介词短语归属不明）。本产品对其采取回避或并列呈现，不做单一断言。 |

# 二：项目背景

## 需求背景

| 场景 | 痛点 | 诉求 |
| --- | --- | --- |
| 成人自学英语者遇到生词，去词典查释义 | 词典给出的是脱离语境的义项列表，学习者不知道该记哪一个；孤立的中文释义记不住也用不出来 | 需要在一个真实、完整的句子里理解这个词怎么用 |
| 拿到一个例句，但看不懂句子结构 | 认识每个单词却读不懂整句，问题出在语法结构而非词汇；市面词典只给例句，不解释句子怎么搭起来的 | 需要同时看到"这个词的用法"和"整句是怎么组织的" |
| 用现成教材或词书学习 | 内容与自身兴趣无关，注意力难以维持，学习中断后不再回来 | 需要学习材料跟随自己当下的兴趣，降低启动成本 |

现有产品的分工是割裂的：词典类产品（欧路、有道）解决查词，不解释句子结构；语法类产品讲解规则，不结合用户当下遇到的词；阅读类产品提供语境，但语境由内容源决定，与用户兴趣无关。

## 项目目标

**北极星指标：单次会话平均生成卡片数 ≥ 3**

选它的理由：这个产品的核心假设是"兴趣驱动的语境化学习能维持注意力"。假设成立的直接表现，就是用户查完一个词之后愿意继续查下一个、或对同一个词再要一句，而不是查完就走。单次会话卡片数直接度量这件事，且由埋点自动产出，不依赖主动反馈。

**辅助指标：**

- 七日主动回访率：首轮推送给目标用户后，一周内在无提醒情况下主动再次打开的用户比例。
- 解析准确率：见第十部分评测方案，作为质量门而非增长指标。

**成本约束：** 单张卡片包含一次生成调用，重试上限 3 次。需记录单卡平均成本与 P95 成本，作为模型选型依据。

## 用户画像

| 维度 | 说明 |
| --- | --- |
| 角色 | 有一定基础、正在自学英语的中文母语成年人 |
| 水平 | 认识常见词但阅读长句吃力，对应 CEFR A2–B2 |
| 场景 | 碎片时间，手机或电脑浏览器，每次 3–10 分钟 |
| 核心任务 | 遇到一个词 → 在自己感兴趣的语境里理解它的用法和所在句子的结构 |
| 技术水平 | 普通网页用户，无学习工具使用门槛 |
| 核心痛点 | 不感兴趣的内容无法维持注意力；孤立释义记不住；句子结构没人讲 |
| 期望 | 我给一个词和一个我感兴趣的话题，你给我一个我读得懂、学得到东西的句子 |

## 原始用户流程（产品上线前）

```text
阅读中遇到生词
  → 打开词典 App 查词（看到 5-8 条无关联的义项）
  → 不确定该记哪条，通常记第一条
  → 想看例句，例句主题随机、与自己无关
  → 遇到看不懂的长句，无处可问
  → 注意力流失，中断
```

产品替代的是"查词 → 选义项 → 找语境 → 理解结构"这一整段。

# 三：产品约束

> 以下七项是既定约束，界定系统行为边界。实现方案在此范围内展开。**约束一至三属于强制底线，不得因开发便利被绕过。**

## 约束一：释义不由模型生成

词典义项来自本地词库，模型**只输出命中的 sense_id，不输出释义文本**。

- 系统按 sense_id 回填词库中的释义原文，前端展示的释义永远来自词库。
- 模型返回的 sense_id 若不在该词的义项集合内，视为结构校验失败，走有限重试。
- 重试仍失败时，降级为"未能判定义项"，展示该词全部义项并标注，**不得由模型补写一条释义**。

> 理由：学习者没有能力识别模型编造的释义，一旦内化则难以纠正。释义幻觉是本产品风险最高的失效模式。

## 约束二：难度由规则引擎判定，不由模型自评

模型不被要求"生成一个 B1 难度的句子"并自我保证。难度判定是生成后的确定性校验：

- 句中除目标词外，超出用户所选等级的词不超过 1 个。
- 句长上限：A2 ≤ 12 词，B1 ≤ 18 词，B2 ≤ 25 词。
- 校验不通过则重新生成，上限 3 次；仍不通过走降级生成并显式标注。

## 约束三：歧义句不做单一断言

- **生成阶段优先回避**：生成后执行歧义检测，命中则重新生成。
- **展示阶段兜底**：若最终仍判定为歧义句，并列呈现两种解析并说明差异来源，不随机选一种断言。

V1.0 需检测的歧义类型限定为三类：介词短语归属、并列成分范围、代词指代对象。其余类型不在本期范围。

## 约束四：语法标签体系固定，不由模型自由发挥

标签集、层级深度与中英文术语对照由本文档第五部分定义，写入 Spec 文档随提示词传入。模型不得使用标签集之外的术语。

> 理由：标签集不固定时，同一用户前后两次查询会看到不一致的术语和粒度，学习者无法建立稳定认知。

## 约束五：解析深度限两层

第一层标注主句成分；第二层标注从句或短语内部成分。**不递归到第三层。**

- 超过两层的复杂句，第三层及以下整体作为一个片段呈现，不再拆解。
- 若生成的句子结构超过两层，视为超出目标难度，触发重新生成。

## 约束六：生词本是本期唯一的留存机制

V1.0 不做复习曲线、不做学习计划、不做进度统计。生词本只提供"保存"与"对已存词再生成一句"两个动作。

## 约束七：交互设计不省略，只改变载体

本项目不产出静态高保真原型，但**交互设计环节不因此取消**。前端开发启动前必须完成两份交付物：

1. **页面状态矩阵**（见 5.6）——每个页面/模块 × 八种状态逐格填写，**不得留空**。留空视为未设计，该模块不得进入开发。
2. **关键交互决策表**（见 5.7）——列出必须由产品经理决定、不交由 AI 默认值处理的交互点，每条写明决策与理由。

视觉方向的确认采用**可运行代表页**而非静态原型：AI 先实现单张卡片页，产品经理确认颜色、字体、密度、圆角与信息层级后，再铺开其余页面。

## 约束八：词性由 NLP 层确定性提供，不由模型标注

与约束一、二同源：能确定性执行的环节不交给模型。

- **词性标注（名词/动词/形容词/副词等）由 NLP 库产出，不进入模型输出契约。** 模型不负责、也不被允许标注词性。
- 词形还原同样由 NLP 层提供，供难度校验使用（约束二）。
- 句子成分（主语/谓语/状语/定语等）由模型标注，因其涉及面向学习者的教学性划分。

> 理由：词性标注是成熟的确定性任务，交给模型既增加成本又引入不必要的错误。

**本期范围变更（V1.0 决策）：** 原计划引入依存句法分析，与模型的成分标注做交叉校验，作为准确率的第二信源。经技术评估，该方案所需依赖的体积与 serverless 部署环境冲突，**本期降级为 P2 不做**。

**补偿措施：** 交叉校验缺席后，成分标注准确率失去自动化保障，**因此将「主干成分准确率」由一般指标提升为上线阻断项**（见第七节）。这是本次降级的交换条件，不可一并省略。

**已知限制：** 每张卡片的成分标注不再有逐条自动校验，质量只在发版评测时抽样保障。

## 约束九：发音音源分层，宁可没有，不给错的

- **单词发音必须来自真人录音库，不得用 TTS 合成单词读音。** 无录音时不显示发音按钮，而不是降级为合成音。
- **例句朗读使用 TTS**，MVP 阶段使用浏览器内置语音合成，不引入云端 TTS 服务。
- 埋点分别记录单词发音与整句朗读的播放率，作为是否引入云端 TTS 的决策依据。

> 理由：学习者会模仿听到的读音。TTS 在单词层面的重音与元音质量不可靠（名动同形词如 record、present 的重音位置常错），读错一个音与给错一条释义属同类错误——学了就难改。整句朗读的风险低得多，学习者听整句是为了感受节奏与连读，不会逐词模仿重音，因此该处使用 TTS 是可接受的妥协。

# 四：功能规划

## 系统构成

| 组成部分 | 职责 |
| --- | --- |
| 学习工作台 | 用户界面：查询输入、卡片展示、生词本 |
| 词库服务 | 单词查询、义项集合返回、词频与等级标签 |
| NLP 服务 | 词性标注与词形还原；确定性执行，不含模型（约束八） |
| 生成能力 | 一次模型调用，产出例句 + sense_id + 成分树，见第五部分 Prompt |
| 校验引擎 | 结构校验、义项存在性校验、难度校验、歧义检测；确定性代码，不含模型 |
| 生词本 | 用户保存的词与卡片，按用户隔离 |

主链路线性固定，不由模型决定下一步：

```text
输入单词 + 兴趣主题
  → 词库取该词全部义项
  → 模型生成（例句 + sense_id + 成分树）
  → NLP 层标注词性与词形还原（确定性，不经模型）
  → 校验引擎四道校验（结构 / 义项 / 难度 / 歧义）
  → 通过：回填释义 + 词性 → 渲染卡片
  → 不通过：重试（≤3）→ 仍失败：降级生成并标注
```

## 核心实体

| 实体 | 说明 | 关键属性 |
| --- | --- | --- |
| 卡片 Card | 一次生成的结果，是展示和评测的最小单位 | 目标词、兴趣主题、难度等级、例句原文、命中 sense_id、成分树、生成状态、是否降级、校验失败原因、耗时、创建时间 |
| 生词本条目 WordEntry | 用户保存的一个词 | 所属用户、单词、保存时间、关联卡片列表 |
| 用户 User | 邀请码登录后的身份 | 用户标识、默认难度等级、默认兴趣主题 |

一个词可对应多张卡片（用户可对同一词多次"再来一句"）。

## 状态定义

**卡片状态**：生成中 → 已完成 / 已降级 / 失败

- 已完成：四道校验全部通过。
- 已降级：重试耗尽仍未通过难度或义项校验，输出结果但前端必须显式标注。
- 失败：模型调用失败或输出无法解析，提供重试入口。

**降级不是失败。** 降级卡片仍向用户展示，但必须带可见提示（如"本句难度可能偏高"），不得静默展示。

# 五：功能需求

## 5.1 语法标签体系（Spec，随提示词传入）

**第一层：句子主干成分**

| 标签 | 中文 | 英文 |
| --- | --- | --- |
| S | 主语 | Subject |
| V | 谓语 | Predicate / Verb |
| O | 宾语 | Object |
| P | 表语 | Predicative |
| C | 补语 | Complement |
| A | 状语 | Adverbial |
| Attr | 定语 | Attributive |

**第二层：从句与短语类型**

| 标签 | 中文 |
| --- | --- |
| CL-N | 名词性从句 |
| CL-REL | 定语从句 |
| CL-ADV | 状语从句 |
| PH-INF | 不定式短语 |
| PH-GER | 动名词短语 |
| PH-PART | 分词短语 |
| PH-PREP | 介词短语 |

**规则：**

1. 每个片段必须且只能有一个第一层标签。
2. 第二层标签只用于说明该片段的内部类型，可为空。
3. 不递归到第三层（约束五）。
4. 不得使用上表之外的术语。
5. 目标词所在片段必须被单独标出。

> 待确认项：本表采用传统五大成分体系，面向中文母语学习者，与国内英语教学术语一致。若开发中发现某类常见句式无法用本表覆盖，应提出增补而非临时造词。

## 5.2 输出结构契约

模型必须返回结构化结果，字段固定：

```json
{
  "sentence": "完整例句原文",
  "sense_id": "命中的义项编号",
  "translation": "整句中文翻译",
  "segments": [
    {
      "text": "片段原文",
      "layer1": "S",
      "layer2": "CL-REL",
      "is_target": false,
      "note": "可选，一句话说明"
    }
  ],
  "ambiguity": null
}
```

**校验规则（确定性代码执行，非模型自检）：**

1. `segments` 拼接后必须与 `sentence` 完全一致（防止模型漏标或改写）。
2. `sense_id` 必须存在于该词的义项集合中。
3. `layer1` / `layer2` 必须在标签集内。
4. 有且仅有一个片段 `is_target` 为真。
5. 难度校验：词表 + 句长（约束二）。
**词性不在本契约中。** 词性由 NLP 层在校验阶段独立产出，与模型输出合并后再渲染，模型无权决定词性。

**原第 6 道依存交叉校验本期不做**，见约束八范围变更。

任一条不通过 → 有限重试 → 仍失败走降级。**校验逻辑必须有独立单元测试，且能脱离模型运行。**

## 5.3 Prompt 设计

```markdown
# 角色
你是一位面向中文母语学习者的英语教师，擅长用学习者感兴趣的语境讲解词汇用法与句子结构。

# 任务
为目标词生成一个例句，判断该词在句中命中哪个义项，并标注句子成分。

# 输入
- 目标词：{word}
- 该词的全部义项（编号 + 释义）：{sense_list}
- 兴趣主题：{topic}
- 目标难度：{cefr_level}

# 生成要求
1. 例句必须自然、真实，符合母语者表达习惯，且与「{topic}」直接相关。
2. 例句必须包含目标词，且该词的用法要能体现所选义项。
3. 句子结构不超过两层（主句 + 一层从句或短语）。
4. 避免生成结构歧义句：不要产生介词短语归属不明、并列范围不明或代词指代不明的句子。

# 标注要求
1. 从给定义项列表中选择一个编号填入 sense_id。**只输出编号，不要自己写释义。**
2. 按给定标签集标注句子成分，标签集见下方。禁止使用标签集之外的术语。
3. 所有片段拼接后必须与例句原文完全一致，不得增删或改写任何字符。

# 标签集
{grammar_spec}

# 输出格式
严格输出 JSON，不要包含任何解释文字或 Markdown 代码块标记。
{output_schema}

# 禁止
- 禁止编造义项列表中不存在的释义
- 禁止输出编号之外的义项信息
- 禁止使用超出目标难度的生僻词
- 禁止标注词性（名词/动词/形容词等），词性由系统独立产出
```

> 手册第九节"格式约束三件套"要求：Prompt 给正反例、解析器兼容多种等价格式、数量类约束不遵守记为质量瑕疵而非解析失败。本 Prompt 已写入反例，解析器实现时需兼容模型偶发的代码块包裹。

## 5.4 词库与 NLP 方案

### 5.4.1 sense_id 锚定在 WordNet 英文义项

**决策（V1.0 确定）：义项列表展示 WordNet 的英文释义，sense_id 使用 synset 编号。中文不与义项对齐，仅作为词级参考单独呈现。**

理由：约束一要求每个义项有稳定编号，WordNet 的 synset 天然满足；而 ECDICT 的中文释义是一整段合并文本（如"n. 银行;岸 vt. 存款"），**不是带编号的独立义项，也无法自动对应到某一个 synset**。技术评估确认这个映射没有现成方案，强行拆分会产生错误对应。

因此本期不做"中文义项列表"，改为：

- **义项列表：英文释义**，命中项高亮，来自 WordNet
- **中文参考：词级一栏**，来自 ECDICT，明确标注为整词参考、不对应具体义项
- 例句的整句中文翻译不受影响，仍由模型生成

**已知代价：**

1. **卡片形态与早期原型演示不同**，原型上的中文义项列表为人工撰写，真实数据不产出该形态。
2. **A2 档位受影响最大**——A2 学习者可能读不懂 WordNet 的英文释义，且其措辞偏书面。建议在阶段一义项粒度验证时一并评估：若 A2 确实不可用，本期收敛为只做 B1/B2 两档。

| 用途 | 方案 | 许可 |
| --- | --- | --- |
| 义项划分与 sense_id | WordNet（Princeton） | 允许商业与研究使用，须保留版权声明、正确引用，且不得以普林斯顿名义宣传 |
| 词级中文参考、词频标注 | ECDICT | MIT |
| 词性标注与词形还原 | 轻量 NLP 库（见技术适配声明） | 依存分析本期不做，见约束八范围变更 |
| 难度分级 | 先用词频分位近似 | CEFR 官方词表存在授权限制，MVP 用近似并显式记录 |

### 5.4.2 合规执行要求（开发阶段直接落实，无需申请流程）

1. 两个数据源的 LICENSE 文件随项目仓库一并保存。
2. 网站页脚标注数据来源与致谢，附 WordNet 官方引用格式。
3. README 写明数据来源与许可类型。
4. **不得在任何页面或宣传中使用普林斯顿大学的名义为产品背书。**
5. MVP 阶段只使用 ECDICT 的基础释义与词频字段，**不展示牛津 3000、柯林斯星级、考纲等第三方标注字段**（这些字段的原始权利归属不清晰，规避）。

### 5.4.3 义项粒度问题（阶段一必须先验证）

WordNet 存在义项切分过细的已知问题——一个常用词可能有十几个 synset，直接全部展示会淹没学习者。

**阶段一验收前必须完成的验证：** 取 20 个常见多义词，人工检查两件事：

1. WordNet 的义项划分是否过细。**判定标准：义项数中位数超过 6 条即需做合并或截断。**
2. WordNet 英文释义的可读性对 A2 学习者是否可接受。若不可接受，本期收敛为 B1/B2 两档。

若确认过细，在产品层处理，二选一：

- 按 WordNet 自带的义项使用频次排序，只展示前 N 条（N 待验证后定）
- 按语义邻近度做义项合并，合并后仍保留原 synset 编号作为 sense_id 的底层锚点

**无论采用哪种，sense_id 必须始终可回溯到原始 synset**，不得因合并而丢失锚点。

### 5.4.4 发音音源（约束九）

| 用途 | 方案 | 说明 |
| --- | --- | --- |
| 单词真人录音 + 音标 | Free Dictionary API（dictionaryapi.dev） | 无需 API key、无需注册，返回音标与发音音频 URL |
| 例句朗读 | 浏览器内置语音合成（Web Speech API） | 纯前端执行，零成本零后端负载，不影响 serverless 部署 |
| 云端 TTS | **本期不做** | 待播放率数据支持后再评估 |

**实现要求：**

- **音频字段必须判空后再渲染按钮。** 部分单词只返回音标而无音频，这是该 API 的已知情况，缺音频时按约束九不显示按钮。
- 音频 URL 随词库一并缓存，不得每次查词都请求外部服务（该 API 为社区免费服务）。
- 英美音区分：接口可能返回多条音标与音频，按用户所选口音优先匹配，无匹配时回落到任一可用录音并标明口音。

### 5.4.5 通用要求

- 词库与 NLP 模型必须本地化或缓存，不能每次查询都走外部 API（成本与延迟）。
- 词库缺词时明确提示"词库中暂无此词"，**不得转由模型生成释义**。

# 七：Eval 与上线质量门

> 本节是本项目区别于普通 Vibe Coding 作品的核心，不得因工期压缩而删减。

## 7.1 评测集构建

- 规模：200 张卡片的金标准。
- 构成：覆盖 A2/B1/B2 三档难度，覆盖单义词与多义词（多义词不低于 60%），覆盖 10 个以上不同兴趣主题。
- 标注：目标词的正确义项、正确成分树、是否为歧义句。
- 标注质量：由本人标注后，请一名英语专业背景人员复核；分歧条目单独记录。

## 7.2 指标与阻断规则

| 指标 | 定义 | 门槛 |
| --- | --- | --- |
| 释义幻觉率 | 输出词库中不存在的释义或无效 sense_id 且未被拦截的比例 | **必须为 0，高危，上线阻断项** |
| 主干成分准确率 | 主语/谓语/宾语标注正确的卡片比例 | **上线阻断项**。依存交叉校验本期不做（约束八），此项是成分准确率的唯一保障，门槛在阶段二首轮评测后冻结 |
| 义项命中准确率 | 命中义项与金标准一致的比例 | 一般错误 |
| 难度符合率 | 通过规则校验的比例（确定性校验，无需人工） | — |
| 降级率 | 降级卡片占比 | 过高说明 Prompt 或难度规则需调整 |

**具体门槛数值在阶段二首轮评测后确定并冻结**，不预设一个无依据的数字。冻结后作为回归基线。

## 7.3 双层验收

按通用技术栈手册第十节，两层都必须做：

- **第一层 mock 自动化测试**：校验引擎的四道校验、状态流转、错误路径、JSON 解析器（纯函数单测是重点，必须离线可跑）。**校验模块不得导入任何模型客户端**，建议加断言强制。
- **第二层真实模型冒烟**：真实 Key 下跑通完整链路，记录真实耗时、首字时间、单卡成本、格式首测合规率与重试后合规率。

**mock 结果不得冒充真实模型验收结果。**

## 7.4 回归触发条件

以下任一变更发生时，必须用同一评测集全量回归：更换模型、更换模型版本、修改 Prompt、修改标签体系、更换词库、更换 NLP 库。
